# Personal AI OS v0.6 封包验收

验收日期：2026-08-24

## 结论

公共仓库可以作为脱敏核心骨架继续发布。它包含长任务拆解、依赖调度、动态路由、模块 manifest、只读工作区摄取、匿名工作流阅读器和全局模块拓扑，不包含私人材料、个人路径、凭据、真实运行正文或未确认许可的媒体素材。

私有开发工作区不能整体推送或批量合并。当前仍有领先提交、活跃未提交修改、分叉历史和无法在有限时间内确认状态的 FileProvider worktree。它们只能作为逐项复用候选，不能被“领先于 main”自动解释为应合并内容。

对公共代码执行了代码关系提取，共识别 36 个代码文件、196 个符号节点和 514 条关系。主要结构中心是计划校验、工作区检查、模块图构建、动态执行路由、任务状态转换和工作台挂载。这与当前产品骨架“摄取 → 规划 → 路由 → 执行合同 → 状态投影”一致。

## 私有开发历史验收

验收只读取 Git 元数据和必要代码，不改写私有状态：

- 私有 `main` 相对其远端领先 158 个提交，远端没有反向领先；
- 只有一条当前功能分支严格领先私有 `main`，包含 3 个科研界面提交，继续保持候选审查状态；
- 一个 detached worktree 存在 15 个已跟踪文件的未提交修改，约 569 行新增、98 行删除，视为活跃写入者；
- 四个 FileProvider worktree 的状态检查在限定时间内未返回，结果记为 `UNKNOWN`；
- 多条历史分支与 `main` 已经分叉。分叉表示两侧都有独立历史，不等于“应该把分支合进 main”；
- 已经包含于 `main` 的旧工作树不重复合并。

因此，本次封包只吸收经过脱敏和重新实现的合同、交互模式与公开 fixture，不复制私有任务正文、Memory、运行回执、科研结论或工作区路径。

## FileProvider 处理

本次只物化 15 个强运行依赖文件：任务 schema、SSE、Execution Broker 入口、Domain adapter 代码与测试、三个合成领域示例、Codex 插件服务与 manifest、以及运行态宠物 SVG。

以下内容保持未下载：

- 普通文稿、公司材料、参考图片、B-roll 和其他音视频；
- 宠物候选集、生成过程文件和来源未确认素材；
- 缓存、历史归档和与当前运行路径无关的附件；
- 可能包含本机配置的 `.mcp.json`。

物化只恢复本机文件块，不代表文件已经通过代码审查、许可审查或公共发布验收。宠物 SVG 仍留在私有素材区，公共演示使用无第三方素材依赖的内置宠物插槽。

## 发布边界

- 公共仓库使用匿名合成数据，任务名称、验收正文、私人输入和真实产物不会进入浏览器 fixture；
- 密钥、账号、模型凭据、本地适配器配置和绝对路径不进入 Git；
- 第三方素材必须同时具备来源、作者和公开许可证，缺一项就留在私有区；
- PolyForm Noncommercial 只授予许可证定义范围内的个人和非商业权利；商业使用需要另签付费书面许可并署名；
- 真实执行版必须在 `run_id`、外部会话标识、事件回读和人工验收全部成立后才能显示“进行中”或“完成”。

## 下一道发布门槛

4. 完成宠物素材许可清单后再加入动画资产；
5. 对私有领先分支逐提交审查，分别决定吸收、保留或放弃，不做全库批量合并。
