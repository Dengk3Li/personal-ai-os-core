# Personal AI OS v0.10 开发任务书

## 目标

把模块地图从工作区组件清单升级为个人 AI 操作系统的递归系统图，并提供可复用的非线性工作流结构。页面必须保留真实依赖、自由画布和模块下钻，同时把私人运行事实与公开展示文案分开。

## 本版交付

### 1. 系统全景与递归下钻

- 顶层主链为：总管入口、个人上下文、领域识别与抽象、长期工作内核、领域工作系统、模型与工具执行、证据验收与交付、经验学习与下一轮。
- 反馈边从经验学习返回个人上下文和长期工作内核。
- 复合模块可以双击下钻；面包屑返回上层。
- 节点保留输入、输出、控制规则、可用状态、上下游和批注入口。
- 运行模块视图继续从 capability manifest 解析真实依赖，不由系统全景替代。

### 2. 工作流结构合同

`personal-ai-os.workflow-structure/v1` 支持以下节点：

- `task`：可分派的原子任务；
- `sequence`：按顺序释放子节点；
- `branch`：并行释放多个路径；
- `join`：按 `all` 或 `any` 汇合路径；
- `if`：按服务端登记的判断条件选择一条路径；
- `loop`：在明确继续条件和最大轮次内重复。

条件不得携带任意表达式。判断结果未知时生成待决定项。循环缺少最大轮次时结构无效。

本版交付结构校验、展平和就绪节点求值。RuntimeStore 与 AutoAdvance 仍按现有依赖合同运行；把结构求值直接接入持久化调度属于下一阶段。

### 3. 本地中文展示包

`personal-ai-os.presentation/v1` 只改变浏览器展示文案，不修改 SQLite 中的任务、状态、上下文或证据。允许字段限定为：

- 工作线：`name`、`caption`、`goal`；
- 任务：`public_label`、`title`、`acceptance`、`agent_role`，以及仅供阅读器使用的 `flow_kind`。

`flow_kind` 只允许 `sequence / branch / join / condition / loop`，不参与调度或状态判断。路径、上下文、Git 收口、凭据、模型载荷和未知字段必须拒绝。浏览器投影把工作线、任务、领域、分组、能力、运行、产物、事件和决定标识替换为稳定顺序别名，写操作由服务端还原到真实标识。展示包保存在私人仓或 Git 忽略目录，公开仓只保留合成示例。

### 4. 中文工作台

- 操作链、工作线、任务、状态、运行事件和决定入口使用可独立理解的中文。
- 一个工作线对应一个分页；页面内纵向阅读目标、结构、任务和运行轨迹。
- 任务节点显示顺序、分支、汇合、条件或循环的结构标签。
- 蓝鲸女仆仍是可选运行宠物，只消费真实或明确标注的演示运行状态。

## 验收条件

1. 系统全景首屏存在真实节点与连线，反馈边可辨认。
2. 双击长期工作内核可以进入内部结构，面包屑可以返回。
3. 工作流结构能够拒绝重复节点、任意条件表达式和无界循环。
4. 未知条件进入待决定，不会自行选择分支。
5. 本地展示包改变浏览器文案后，SQLite 原始值保持不变。
6. 私人上下文、本机路径和凭据不能进入展示包或浏览器投影。
7. 桌面与手机页面均可读取；画布支持拖动、平移、缩放和适应视口。
8. 全量 Python 与 Workbench 测试、差异检查和敏感信息扫描通过。

## 下一阶段

- 把 `WorkflowStructure` 的就绪节点结果接入 RuntimeStore 与有界自动推进。
- 为循环轮次、条件结果和汇合状态增加持久化事实。
- 将模块 manifest 扫描扩展为递归子图与输入输出端口发现。
- 增加持久化模块开关、核心模块锁定和停用后的依赖传播；本版状态标签不等于启停控制。
- 把经过授权的历史对话先生成经验候选，再经证据核验和人工确认进入任务级上下文。
