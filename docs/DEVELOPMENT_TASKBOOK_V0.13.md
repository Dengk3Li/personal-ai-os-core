# Personal AI OS v0.13 开发任务书

## 交付目标

把个人 AI 系统的“脑”和“手”连接到同一份运行事实：工作方式先形成有证据、可审核的候选；任务卡用明确关系连接正在建设或使用的系统模块。学习、任务状态和模块结构分别保留清晰权威。

## 已交付范围

### 有边界的工作方式

- `personal-ai-os.memory-candidate/v1` 区分个人与团队、领域、类别、证据、样本数和隐私等级。
- 新候选只能从 `PROPOSED` 开始；显式审核必须记录非空审核主体，接受或拒绝事件追加保存。
- 模型上下文只装入与当前任务主体和领域同时匹配的 `APPROVED` 规则及其证据引用；单条规则、规则数量和模型上下文总字符数均有上限。
- 工作台只投影候选数、已确认数和主体数，不把工作方式正文发送给浏览器。

### 模块与任务联动

- `personal-ai-os.module-task-link/v1` 支持 `BUILDS / CHANGES / USES / VALIDATES / BLOCKED_BY / AFFECTS` 六类关系。
- 人工明确关系和导入关系默认可确认；自动分析关系必须先保持 `PROPOSED`。
- 模块地图显示关联任务数和建设中任务数，模块详情可以跳到任务卡；工作流节点显示已确认的模块关系。
- 未关联任务单独保留，避免系统图掩盖孤立工作。
- 模块批注创建任务时保留结构化模块标识，不再只写入自然语言标题。

### 私人旧卡接入边界

- 私人仓库复用现有任务卡解析器和任务上下文投影，不在公开仓复制私人卡片、路径、工作线名称或领域映射。
- 首次接入仅生成只读 `TaskEnvelope/v1` 预览、稳定去重键和 reconciliation issues。
- 卡片状态是当前权威；追加事件只用于对账，不能覆盖卡片状态。
- Domain 和缺失上下文保持 `UNKNOWN`，不按名称猜测。

## 设计参考

- Prime Agent：长期目标与单次 continuation 分离，队列和恢复信息持久化。
- LangGraph：checkpoint、interrupt 和至少一次恢复语义，副作用需要幂等边界。
- OpenHands：append-only 事件、执行服务与持久记忆分层。
- Letta Code 与 Mem0：持久工作记忆、主体和领域作用域。
- Backstage：显式实体关系和由正向关系派生的反向视图。

本项目只吸收通用机制并独立实现，许可证条件见 `REFERENCE_PROJECT_LICENSES_V0.13.md`。

## 验收

- 173 个 Python 用例通过。
- 60 个 Workbench 用例通过。
- 未经人工确认的候选不会进入模型上下文。
- 其他主体或其他领域的规则不会进入当前任务。
- 已确认模块关系在模块地图和任务卡两端一致可见。
- 自动分析关系保持候选，未关联任务仍可见。
- 公开安全投影不会泄露真实模块标识。

## 未交付边界

- 没有自动读取全量历史对话、自动归纳个人或同事习惯、自动解决冲突或自动批准经验。
- 没有把 `WorkflowStructure` 直接绑定到持久化 AutoAdvance，也没有后台 daemon、流式执行、取消或外部运行自动对账。
- 没有能力插件自动安装、自动启用或系统自我修改；发现、许可证核对、权限、验证和人工提升仍需独立闭环。
- `privacy_class` 当前只用于候选审阅，不承担执行授权；新插件模块标识尚未与一个权威目录做 unresolved-link 验证。
- 私人旧卡预览不等于已导入 RuntimeStore；状态差异和 Domain 映射需要人工处理。
- 真实科研任务尚未在本版本中启动，接入时必须先确认任务范围、数据权限、运行资源和验收标准。
