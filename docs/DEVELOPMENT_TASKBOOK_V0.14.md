# Personal AI OS v0.14 开发任务书

## 目标

把“会读取记忆”从提示词约定改成运行时合同，同时把执行配置移出台前，并补齐模块下钻后的跨层连接。

## 已交付

- 工作流可指定 `personal-ai-os.work-protocols/v1`。
- Broker 在领取执行权前解析工作协议；协议缺失时任务保持 `QUEUED`，不创建 run，不调用模型。
- 工作协议可以指定个人或团队记忆主体。任务会自动读取当前领域中已经确认的工作习惯。
- 会议纪要预设绑定来源优先的完整记录协议，明确原始逐字记录、完整信息、自然讨论顺序、精确数字与归因要求。
- 成功运行登记 `MEMORY_REVIEW_REQUESTED`；候选的生成、证据补充和审核仍保持独立，不自动写入长期记忆。
- 模型、路由、执行适配器和 API 状态进入后台“设置”；任务卡与工作线不再提供重复配置控件。
- 自动路由模式支持从单个任务卡直接使用服务端已保存的路由。
- 模块地图区分“系统全景”和“组件依赖”。个人上下文与长期工作内核均可下钻。
- 子图保留所属上层模块，以及跨层输入、输出和反馈关系。

## 验收边界

- 工作协议、模板规则与已确认习惯共同受 12,000 字符模型上下文预算约束。
- 协议 schema 不提供凭据字段，加载器拒绝常见密钥、凭据赋值和带 userinfo 的 URI。真实密钥只允许来自服务端环境变量；未知格式仍需在本地配置评审中排除。
- `MEMORY_REVIEW_REQUESTED` 只是复核入口，不是经验候选，更不是已确认记忆。
- 自动读取仅作用于明确绑定协议的工作流，以及主体和领域同时匹配的已确认习惯。
- 历史对话自动检索、候选提取、冲突合并、模板版本选择和记忆过期仍未交付。

## 验证

- 181 个 Python 用例通过。
- 65 个 Workbench 用例通过。
- 工作协议缺失、上下文超限和执行配置未就绪均在模型调用前停止。
